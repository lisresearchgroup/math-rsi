# 推导与证据说明：基码 74-42，A 型，目标格 [74,43]，目标距离 12

## 来源说明（不作为证据）

- 基码 B = `[74,42]`，校验矩阵 H 为 32×74，列整数由 `base.cols` 给出（`SPEC_TOOLS.md` 第 1 节：第 j 列整数 = Σ H[i][j]·2^i）。
- 分层程序 layers3 的结果 `raw.json`（sha256 见 `build.json`）给出：深度（陪集最小重量）≥ 12 的伴随式存在。
  取 `free` 中 t = depth−1 = 11 一项的第一个代表 s = 980558980（`s.txt`，十进制），即 s ∉ L_11(H)，depth(s) ≥ 12。
- 取 x 使 H x = s：对 H 的列做贪心线性无关选取，把 s 用选出的列线性表示，未选出的列（自由变量）取 0。x 见 `x.txt`（74 位）。
- G_B 取 H 的核的一组基（42 行）：每个相关列 j 给一个向量 e_j + （前面无关列的组合）。
- A 型（加一行）：最终码 = B + ⟨x⟩，生成矩阵 [G_B; x]，参数 [74,43]。
- 来源推导：新码字要么在 B 中，要么落在陪集 x+B 中，故距离 = min(d(B), depth(s)) ≥ 12。
  这一推导依赖 layers3 的结果与 depth(s) ≥ 12，**只是来源说明，不作证据**。

## 证据（本目录文件里可复核的东西）

1. `G.txt`：最终码的生成矩阵，43 行 × 74 列，坐标顺序 = `base.cols` 的列顺序。
2. 秩证据（`build.json` 的 `rank_evidence`，由 `hit_process.py` 用整数异或消元算出）：
   rank(H) = 32（应为 ρ = 32）；rank(G_B) = 42（应为 k0 = 42）；rank(G) = 43（应为 K = 43）；
   G_B·Hᵀ = 0：通过；H·x = s：通过。
3. 距离证据：对 `G.txt` 由两套互相独立的程序做完整、无抽样的验距（判定 d(C) ≥ D，D = 12），
   结果在 `verify_A.json`（`tools/verify_a/`，方法见其 `METHOD.md`）与 `verify_B.json`（`tools/verify_b/`，若已运行）。
   任一程序判假时给出重量 < D 的非零码字作见证，并由 `hit_process.py` 另行核对该见证确在行空间内。
4. `novelty_codetables.json`、`codetables_live.html`：取回码表实时页面时的下界/上界（只是查新记录）。
5. `STATUS.json`：验收汇总；`verified` 要求秩证据全部通过、A 与 B 都判真、且目标距离 > 码表实时下界。

上面第 2、3 点是证据；"来源说明"部分的推导即使有误，也不影响 G 的验收结论，因为验收只看 G 本身。
